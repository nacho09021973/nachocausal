# PR-003 C1 reference alternatives — order-only `R` candidates

Status: **dev conceptual note, no code, no data, no freeze, no result**.

Context: comité 009 and `tests/test_c1_selector.py` closed the draft
`R=Max(C)` negatively. In any finite nonempty poset, `down(Max(C)) = C`, so
`B_R = empty` and `H[C;R] = empty`. The next C1 question is not how to tune a
score; it is how to define a nontrivial relational reference `R` without
coordinates, embedding, or post-hoc choices.

Binding requirement for every candidate below:

```text
R must be order-only, relabel-conjugate, selected before scoring, and not force
down(R)=C by finite-poset logic.
```

However, this requirement is only a Guard-v floor. It is not enough to show
scientific relevance. A deterministic, relabel-invariant, order-only nontrivial
selector can be built from many finite-poset profiles without representing a
physical membrane. Any candidate must also face the stronger question recorded
in `dev/PR003_COMPLETION_TRUNCATION_NONIDENTIFIABILITY.md`: whether the same
finite order-only subposet can have two physically admissible completions that
induce incompatible C1 references or decisions. If yes, R1/R2/R3 are not missing
implementation details; they are trying to reconstruct information not present
in the finite order.

## Candidate R1 — chain-end reference inside a selected ideal

**Idea.** Use the formal split now in Lean:

- `IdealEnd` selects an ambient non-principal ideal;
- `ChainEnd` represents a cofinal direction inside it;
- a finite approximation to that direction supplies the reference subset `R`.

**Order-only sketch.**

1. Select an ambient lower set/ideal candidate `I(C)` by a fixed order-only rule.
2. Select a non-terminal cofinal-chain representative class inside `I(C)` using
   only order invariants.
3. Let `R` be a finite terminal segment / frontier of that cofinal direction,
   not the set of all maximal elements of `C`.

**Why it might avoid triviality.** If `R` is internal to a selected direction
inside an ideal rather than all future maximals, `down(R)` need not be all of
`C`.

**Open blockers.**

- `I(C)` selection is not defined.
- Finite approximation to a non-terminal cofinal direction is not defined.
- Need a proof/test that the rule can yield `down(R) != C` on finite synthetic
  posets without using geometry.
- Risk: selecting `I(C)` after seeing behavior would become post-hoc tuning.

Status: `OPEN_REQUIRES_FORMAL_SELECTOR`.

## Candidate R2 — filtered maximal reference

**Idea.** Keep maximal elements as an available finite boundary, but do **not**
use all of them. Select a proper subset `R ⊂ Max(C)` by an intrinsic,
predeclared filter intended to represent a persistent escape sector rather than
the whole sampling wall.

**Order-only sketch.**

1. Compute `Max(C)`.
2. Compute order-only profiles of maximal elements, e.g. past-size profile,
   height profile, cover-degree profile, or overlap of pasts with level sets.
3. Select a subset of maximals by a closed rule on those profiles.
4. Build `H[C;R]` from that subset.

**Why it might avoid triviality.** A proper subset of maximals can have
`down(R) != C`, so `B_R` and `H[C;R]` may be nonempty.

**Open blockers.**

- The filter is currently not defined.
- Many profile filters are sampling-wall detectors in disguise.
- Any threshold, percentile, or clustering rule must be fixed before data.
- Need Guard-v on the subset selection and tie-breaking.

Status: `OPEN_HIGH_WALL_CONFUND_RISK`.

## Candidate R3 — dynamic reachability / growth-flow reference

**Idea.** Define `R` through a deterministic order-only flow rather than static
maximal elements. Starting from an internal seed set chosen by order invariants,
iterate a reachability rule forward and let `R` be the flow's non-captured
frontier.

**Order-only sketch.**

1. Choose seed level(s) using intrinsic height or rank-like order data.
2. Propagate forward by cover links or future reachability.
3. At each step, retain elements satisfying a closed reachability criterion.
4. Let `R` be the terminal frontier of the retained flow, or the set of flow
   endpoints that remain mutually reachable under the rule.

**Why it might avoid triviality.** The reference is generated by an internal
process and need not include all maximals. It may define a nontrivial
`down(R)` even in a finite patch.

**Open blockers.**

- Seed-level rule is not fixed.
- Flow retention criterion is not fixed.
- Persistence/asymmetry may get baked into `R` instead of measured after `R`.
- Needs proof that relabel-conjugacy holds for all tie-breaking.
- Needs a proof/spec that the flow terminates or otherwise returns a well-defined
  finite reference set.
- Needs an explicit rule for bifurcations, equivalent branches, and multiple
  equivalent attractors.
- Must not hide free parameters in stopping rules, branch selection, or
  frontier compression.

Status: `OPEN_MOST_PROMISING_IF_RULE_CLOSED`.

| R2 filtered maximals | simplest finite replacement for `Max(C)` | wall detector / threshold tuning | `OPEN_HIGH_WALL_CONFUND_RISK` |

## Status before any code

Do not implement any of the three candidates yet. The immediate committee
question is not which selector to develop, nor whether a nontrivial canonical
selector exists abstractly. The next question is:

```text
Can the same finite order-only subposet admit two physically permitted
completions that induce incompatible C1 decisions on the shared subposet?
```

If the answer is yes, the obstruction is:

```text
COMPLETION_AND_TRUNCATION_NONIDENTIFIABILITY
```

and selector development should pause. If the answer is no, or only holds for
inadmissible completions, R1/R2/R3 can be reconsidered under stronger obligations:

```text
order-only
+ deterministic
+ equivariant
+ nondegenerate
+ stable under sprinkling and truncation
+ convergent toward the intended geometric reference object
+ Guard-v-checkable
```

Automorphism-based no-go reasoning is not enough for this decision. Equivariance
under `Aut(C)` prevents selecting an individual representative in a nontrivial
orbit, but still allows selecting whole orbits, unions of orbits, invariant
antichains, or invariant global subsets. Generic finite sprinklings may also
have trivial automorphism group.

Recommended verdict vocabulary for the next committee:

```text
COMPLETION_NONIDENTIFIABILITY_PLAUSIBLE_FORMALISE
COMPLETION_NONIDENTIFIABILITY_NOT_ESTABLISHED_RETURN_TO_R_SELECTOR
NEEDS_PRECISE_COMPLETION_CLASS
```
