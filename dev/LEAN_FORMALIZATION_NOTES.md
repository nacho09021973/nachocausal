## 2. Definitions to align with mathlib

### 2.1 Poset

Use mathlib's existing `[Preorder P]` / `[PartialOrder P]` hierarchy. Prefer `[PartialOrder P]` for causal
sets to avoid quotienting antisymmetry issues.

### 2.2 Ideal

Use `Order.Ideal P` when possible, not a new bespoke structure. In mathlib this means:

- nonempty;
- downward closed;
- upward directed.

This is stronger than a bare down-set. If project prose says "ideal" but means "down-set generated by a
set", formalise that as a `LowerSet` or `Set.Iic`/principal lower set first, then upgrade only when the
directed/nonempty hypotheses are available.

### 2.3 Principal ideal

Use `Order.Ideal.principal p`. In mathlib, membership is expected to reduce to `x ≤ p` via
`Order.Ideal.mem_principal`.

Project translation:

```
principal(p) = ↓p = {x : x ≤ p}
```

### 2.4 Bounded ideal

The prose statement "every bounded ideal is principal" must be made precise. The correct Lean-friendly
statement is:

```
If I : Order.Ideal P has an upper bound b and P is locally finite enough that the set I is finite,
then I has a maximal element m; directedness then implies every x ∈ I satisfies x ≤ m, hence
I = Order.Ideal.principal m.
```

The real theorem is not true from "bounded" alone in arbitrary posets. It needs either:

- finite carrier `I`;
- or local finiteness plus a proof that the bounded lower interval below `b` is finite.

This is the first place where exact hypotheses matter.

## 3. First Lean targets

### L0 — ideal with maximum element is principal

Mathematical statement:

```
If I is an ideal and m ∈ I is maximum in I, then I = principal(m).
```

Expected proof:

- `I ⊆ ↓m` by maximality;
- `↓m ⊆ I` by downward closure and `m ∈ I`;
- extensionality.

Status: `FORMALISED` in `formal/HorizonFormal/HorizonFormal/Ideals.lean` as
`ideal_eq_principal_of_hasMaximum`. This theorem avoids all local-finiteness machinery and is now the
base lemma for L1.

### L1 — bounded locally finite ideal is principal

Mathematical statement:

```
Assume every interval {x | x ≤ b} is finite. If I is an ideal and I ⊆ ↓b, then I is principal.
```

Expected proof:

- view `I` as a finite nonempty subset of `↓b`;
- choose a maximal element `m ∈ I`;
- use directedness to show `m` is actually maximum in `I`: for any `x ∈ I`, directedness gives
  `z ∈ I` with `x ≤ z` and `m ≤ z`; maximality of `m` in the finite subset forces `z = m`;
- apply L0.

Risk:

- mathlib may already have a version; search before writing.
- "locally finite" in mathlib may be encoded by `LocallyFiniteOrder` and finsets of intervals. Confirm
  exact APIs before implementing.

Progress:

- `FORMALISED L1a`: `isPrincipalIdeal_of_finite` in `formal/HorizonFormal/HorizonFormal/Ideals.lean`.
  It proves that every finite mathlib `Order.Ideal` is principal.
- `FORMALISED L1`: `isPrincipalIdeal_of_bounded_of_finite_Iic` in
  `formal/HorizonFormal/HorizonFormal/Ideals.lean`. It proves the prose version after the exact
  hypothesis is made explicit: an upper bound `b` plus finiteness of the lower interval `Set.Iic b`.

### L2 — non-principal ideal yields cofinal sequence under countability

Mathematical statement:

```
If P is countable and I is a non-principal ideal, then I admits a countable cofinal chain/sequence.
```

Hypotheses to refine before Lean:

- `I` is countable or `P` is countable;
- chain may be nondecreasing sequence `c : Nat -> P` with `c n ∈ I`, `c n ≤ c (n+1)`;
- cofinal in `I`: for every `x ∈ I`, exists `n`, `x ≤ c n`;
- non-principal should imply no terminal maximum, otherwise L0 would make it principal.

Expected construction:

- enumerate `I`;
- recursively use directedness to choose an upper bound in `I` for previous `c n` and the next enumerated
  element;
- prove monotone/cofinal.

This may overlap with `Order.sequenceOfCofinals` / `Order.idealOfCofinals`, so inspect mathlib first.

### L3 — image/preimage behaviour of ideals under monotone maps

Split this into safe sublemmas:

1. Preimage of an ideal under a monotone map is a lower directed set only if the map has enough
   cofinal/lifting structure. Plain monotone maps preserve lower-closedness in preimage, but not
   nonemptiness/directedness automatically in every useful direction.
2. Image of an ideal under a monotone map need not be downward closed unless the map is an order embedding
   with an appropriate lower-reflection property or the image is downward closed in the codomain.

Therefore do **not** write "Idl is functorial under monotone maps" as a single broad theorem yet. The
first formal target should be:

```
Order embedding e : P ↪o Q preserves principal ideals:
x ∈ principal p  ↔  e x ≤ e p
```

Then define the correct ideal-map only after the needed closure hypotheses are explicit.

### L4 — ideal ends under embeddings

Do not formalise until "ideal end" is fixed. Candidate definition:

```
IdealEnd(P) = { I : Order.Ideal P // ¬ ∃ p, I = principal p }
```

But this treats every non-principal ideal as an end, which may be too broad for causal-set/GKP use.
Before Lean, decide whether ends are:

- all non-principal ideals;
- maximal proper non-principal ideals;
- indecomposable past/future sets with terminality constraints;
- equivalence classes of cofinal chains.

Lean target after definition is fixed:

```
An order isomorphism preserves and reflects principality, hence preserves IdealEnd.
```

Use isomorphism first, not arbitrary embedding. Embeddings require extra hypotheses to preserve
non-principality in the codomain.

Progress:

- `FORMALISED`: `mapIdealOrderIso` transports mathlib ideals across an order isomorphism.
- `FORMALISED`: `mapIdealOrderIso_principal`, `isPrincipalIdeal_mapOrderIso`,
  `isPrincipalIdeal_of_mapOrderIso`, and `isPrincipalIdeal_mapOrderIso_iff` show principality is
  preserved and reflected by order isomorphisms.
- `FORMALISED`: `mapIdealEndOrderIso` transports the provisional non-principal-ideal end notion across
  order isomorphisms.
- Still `HYPOTHESES_OPEN`: arbitrary embeddings. They can create new lower elements in the codomain
  unless the image is lower-closed or the embedding is upgraded to an isomorphism onto a lower suborder.

## 4.1 Accessibility result

`FORMALISED` in `formal/HorizonFormal/HorizonFormal/Accessibility.lean`:

- `accessesIdeal_iff_mem`: for a mathlib `Order.Ideal I`, accessibility `x ⇝ I` defined as
  `∃ y ∈ I, x ≤ y` is equivalent to `x ∈ I`.
- `relationalPastOfIdeal_eq`: the relational past of an ideal is the ideal itself.

Consequence for the horizon notes: if the reference object is already packaged as an ideal, then the
"past of escape" adds no new structure. A nontrivial `R`-based horizon should start from a reference
subset/family and then take its generated lower closure, not silently assume an arbitrary ideal while
expecting extra accessibility content.

## 4.2 Relational horizon triviality checks

`FORMALISED` in `formal/HorizonFormal/HorizonFormal/Horizon.lean`:

- `relationalPast_empty`: empty reference has empty relational past.
- `relationalHorizon_empty`: empty reference has empty horizon.
- `relationalPast_univ`: total reference has total relational past.
- `relationalBlackRegion_univ`: total reference has empty black-region complement.
- `relationalHorizon_univ`: total reference has empty horizon.

These are deliberately elementary, but they are useful guardrails: a nontrivial finite relational horizon
requires a nonempty, non-total, internally justified reference subset `R`.
